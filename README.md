# 🌤️ Небесная погода

Веб-приложение, которое объединяет **погоду**, **солнечную активность**, **Луну** и **геомагнитное поле Земли** на одной странице. Тёмная тема по умолчанию, адаптивный дизайн, графики на Recharts. API-ключи **не нужны**.

**Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Recharts · suncalc**

## Возможности

| Раздел | Что показывает |
| --- | --- |
| 🌦️ Погода | Текущая погода по геолокации (или выбранному городу): температура, ощущаемая, влажность, давление, ветер (скорость, направление, порывы), осадки, облачность, УФ-индекс, видимость, восход/закат. Почасовой прогноз на 24 часа и прогноз на 7 дней. |
| ☀️ Солнце | Число солнечных пятен, поток F10.7, вспышки C/M/X за 7 суток, вероятность вспышек M/X, вероятность геомагнитной бури, радиоблэкаут (R-шкала), график активности за 14 дней, фаза и график 25-го солнечного цикла (с прогнозом). |
| 🌙 Луна | Фаза и освещённость, возраст, расстояние, восход/закат, ближайшие новолуние и полнолуние, высота и азимут (с «картой неба»). |
| 🧲 Геомагнитное поле | Текущий Kp и G-шкала NOAA, классификация (спокойно / слабая / умеренная / сильная буря), график Kp за 24 часа, прогноз Kp на 3 дня с вероятностью бури, пояснение о влиянии на самочувствие и связь. |

Дополнительно: поиск города (автодополнение), кнопка «моё местоположение», запоминание города в `localStorage`, независимые состояния загрузки/ошибок для каждого раздела (если один источник недоступен — остальные продолжают работать), автообновление данных.

## Источники данных

| Данные | Источник | Ключ |
| --- | --- | --- |
| Погода и прогноз | [Open-Meteo Forecast API](https://open-meteo.com/en/docs) | не нужен |
| Поиск городов | [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) | не нужен |
| Название города по координатам | [BigDataCloud client reverse geocode](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api) | не нужен |
| Kp-индекс, прогноз геомагнитной активности | [NOAA SWPC](https://services.swpc.noaa.gov/) (`products/noaa-planetary-k-index-forecast.json`, `text/3-day-geomag-forecast.txt`, `json/planetary_k_index_1m.json`) | не нужен |
| Солнечные пятна, вспышки, цикл, вероятности | NOAA SWPC (`json/solar_regions.json`, `json/goes/primary/xray-flares-7-day.json`, `json/solar-cycle/*`, `json/solar_probabilities.json`, `products/noaa-scales.json`) | не нужен |
| Луна (фаза, положение, восход/закат) | расчёт локально — [suncalc](https://github.com/mourner/suncalc) | не нужен |

### Кэширование

Запросы к внешним API идут **только через серверные роуты** Next.js (`/api/*`) и кэшируются через `fetch(..., { next: { revalidate } })` плюс `Cache-Control: s-maxage` (CDN Vercel):

| Роут | revalidate |
| --- | --- |
| `/api/weather` | 10 мин |
| `/api/geomag` | 5 мин |
| `/api/sun` | 15 мин |
| `/api/geocode`, `/api/reverse` | 1 час / 24 часа |

Если API недоступен, роут возвращает `502` с понятным сообщением, а интерфейс показывает заглушку с кнопкой «Повторить» — приложение не падает.

> Примечание: «число солнечных пятен» на карточке — оперативная оценка по последнему отчёту NOAA о солнечных регионах (число Вольфа = 10 × группы + пятна). Месячный индекс SSN приведён в блоке «Солнечный цикл».

## Структура проекта

```
src/
├── app/
│   ├── api/
│   │   ├── weather/route.ts   # Open-Meteo → нормализованный JSON
│   │   ├── geomag/route.ts    # Kp, история, прогноз, вероятности бурь
│   │   ├── sun/route.ts       # пятна, вспышки, цикл
│   │   ├── geocode/route.ts   # поиск городов
│   │   ├── reverse/route.ts   # координаты → название
│   │   └── health/route.ts    # healthcheck
│   ├── layout.tsx, page.tsx, globals.css
├── components/                # Dashboard, *Section, MoonPhase, LocationSearch, ui
├── hooks/useFetch.ts          # загрузка + авто-обновление + ошибки
└── lib/
    ├── weather.ts, geomag.ts, sun.ts   # серверные клиенты API
    ├── astro.ts                         # Луна (suncalc)
    ├── kp.ts                            # классификация Kp, советы
    └── format.ts, wmo.ts, types.ts, api.ts
```

## Запуск локально

Требуется Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:3000
```

Продакшен-сборка:

```bash
npm run build
npm run start
```

## Переменные окружения

**Для работы приложения переменные окружения не требуются.**

`DATABASE_URL` используется только служебным роутом `/api/health` в среде разработки (шаблон проекта включает Drizzle + PostgreSQL). Если переменная не задана (как на Vercel), health-check просто возвращает `{ "ok": true, "db": "skipped" }`. Пример — в `.env.example`.

## Деплой на Vercel

**Вариант 1 — GitHub → Vercel (рекомендуется):**
1. Откройте [vercel.com/new](https://vercel.com/new) и импортируйте репозиторий.
2. Framework Preset — Next.js (определится автоматически). Переменные окружения не нужны.
3. Нажмите Deploy. Дальше каждый push в `main` деплоится автоматически.

**Вариант 2 — Vercel CLI:**
```bash
npm i -g vercel
vercel login
vercel link
vercel --prod
```
(В CI можно использовать `--token $VERCEL_TOKEN`.)
